# 会话名称与原生名称同步

## 行为

- 会话标签名称与工作区名称是两套独立信息。侧栏工作区重命名不修改会话或原生名称。
- Claude、Codex、OpenCode、Pi 和 OMP 的会话重命名先写原生，成功后保存 Paseo 投影；不发模型提示词、不分叉会话、不改正文。
- 原生会话尚未建立时不能写原生名。改名失败时弹窗保留输入并显示错误，可原地重试。
- 无原生改名接口的提供方保留本地别名，包括已有的未标记旧名称。不能把“Paseo 名称已变”作为原生改名成功的依据。
- 连接后的首个会话目录请求启动一次后台名称同步，同一时间的多个客户端复用进行中的扫描；恢复运行时也读取当前原生名称。此过程不阻塞目录首屏，不改变工作区、归档状态或会话身份。
- 读取失败保留当前名称并记录完整错误；下次连接或恢复再次读取。不以读取失败代替空名称，也不把未找到的原生会话当作删除指令。
- 旧 Paseo 名称保存在智能体记录的 `titleSync.legacyTitle`。普通快照写入必须保留标题同步信息，已成功改名或迁移的记录标记为已迁移，防止旧名再次覆盖新选择。

## 迁移旧会话名称

脚本只能连接已更新的守护进程。它校验 `--home` 中的主机身份与实际连接一致，不允许把一个主机的记录写到另一个主机。脚本不会重启守护进程，也不会执行模型提示词。原生写入可能需要恢复目标运行时，恢复失败会逐项记录为失败。

先构建本地依赖，更新主机后预览。以下命令只作为操作说明，不代表已执行真实迁移：

```powershell
npm run build:server
npx tsx scripts/migrate-session-titles.mts --home "$env:USERPROFILE\.paseo" --report '.output\session-titles-preview.json'
```

检查报告中的目标名称、原生旧名称、冲突及不支持项，确认后用另一个报告文件执行：

```powershell
npx tsx scripts/migrate-session-titles.mts --home "$env:USERPROFILE\.paseo" --report '.output\session-titles-applied.json' --apply
```

开发守护进程需显式指定开发目录和地址：

```powershell
npx tsx scripts/migrate-session-titles.mts --home '.dev\paseo-home' --host '127.0.0.1:6768' --report '.output\dev-session-titles-preview.json'
```

- 默认排除归档会话；需要时添加 `--include-archived`，不会取消归档。
- 报告包含会话名称，属于本地敏感数据，不应提交到 Git。报告首次创建拒绝覆盖已有文件，后续采用原子更新。
- 首先保存全部候选旧本地名，再读取旧原生名；任何原生写入之前必须成功保存完整预览。
- 同一原生会话存在不同旧名时标记冲突，不自行选择；相同名称只迁移一次，并同步同主机上指向该原生会话的 Paseo 记录。
- 旧记录没有“用户手工命名”标记，无法可靠区分自动名称和手工名称，因此预览列出所有非空旧会话名称，必须检查，不按标题内容猜测。
- 写入前核验原生会话身份和名称，若发生变化则拒绝覆盖。原生接口不提供跨外部客户端的原子比较写入，迁移期间请不要同时在其他客户端改名。
- 原生不支持的项目保留别名；失败或冲突使脚本非零退出，详情在报告中。重跑会跳过已成功迁移的记录，需使用新的报告文件。
- 报告保留旧原生名称。需要撤回时可在原生客户端按报告逐项改回，之后重新打开 Paseo 读取；脚本不会自动批量回滚已成功的项目。
