# 会话正文搜索

侧栏搜索与快捷键打开同一个命令中心。输入关键词后，先显示本地标题、工作区等匹配，再异步补充会话正文命中，按会话去重；正文结果显示主机和命中摘要，点击打开原会话。切到专用文件搜索范围时不查询正文。

## 范围与数据归属

- 查询当前客户端目录中未归档的 Paseo 会话，并按各自 Host 分组，在目标主机上匹配。不同主机的同名/同 ID 会话互不混淆。
- 搜索用户与助手正文，含主机已经保存、但前端尚未加载的旧历史，也包含运行中的最新文本；不是只搜浏览器缓存。
- 不解析附件图片的 OCR、不扫描整个项目文件、不把推理、工具原始输出或配置密钥当成正文，也不自动导入提供方未导入的原生会话。
- 搜索不会创建、恢复或运行提供方会话；合并已保存会话目录和当前运行目录，通过 AgentManager 的只读搜索方法读取持久时间线与当前内存时间线。重启后尚未打开的会话也能匹配；首次尚未由 Paseo 同步的原生历史不会被凭空搜索出来。

## 交互与性能

输入防抖 250 毫秒，每个主机最多返回 100 个会话摘要；摘要截取至 180 字符，大小写与全半角统一，多个词要求在同一条正文中全部出现。现有标题匹配排在正文匹配之前，点击仍使用既有会话导航，不新增有副作用的恢复路径。

主机最多同时读取两条会话历史，扫描长历史时定期让出事件循环；新查询会使同一连接旧查询停止继续扫描，客户端也会丢弃过时结果，关闭搜索时不再套用迟到响应。不同 Host 的错误分别展示，成功主机结果仍可使用。

加载状态显示“正在搜索会话正文”；失败显示主机和具体原因，保留重试按钮与本地标题结果，不把失败说成“没有匹配”。需要该 Host 声明 `server_info.features.conversationSearch`，旧主机明确要求更新，不通过拉取数千次旧历史 RPC 伪装降级实现。

## 协议与权限

`agent.conversations.search.request/response` 使用相关请求标识，查询和目标会话在请求顶层，结果位于响应 payload。新能力字段可选，现有消息格式不改变。读写授权表将请求与响应均归于 `workspace.read`；服务端仅接受公开且未归档会话目录中的目标 ID，不搜索 internal 会话。

实现分别位于协议 `messages.ts`、客户端 `daemon-client.ts`、服务端 `session.ts` 与 `agent/conversation-search.ts`，以及前端 `command-center/conversation-search.ts`、`use-conversation-search.ts`。测试覆盖磁盘旧历史、归一化、限额、取消、失败不冒充空结果、跨主机隔离和客户端 RPC 关联。
