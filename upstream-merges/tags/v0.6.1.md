## 已合并

### `8bfae1585` 切分支后当前拉取请求消失，或被已合并的旧请求触发误归档

**做什么**
拉取请求状态改为跟随当前实际检出的分支。自动归档只有在守护进程先看到同一请求处于打开状态、随后看到它已合并，并再次读取权威状态确认后才会执行；首次打开已经合并的旧请求、切换到另一个已合并请求以及手动恢复工作区都不会误归档。

**对二开的影响**
服务端 Git 检出事实是二开 Git 面板的公共支撑，但没有合并任何上游 Git 面板界面。二开此前缺少上游分支绑定前置，因此同步引入本地分支绑定：Paseo 内重命名会迁移原请求身份，智能体直接切换或重命名后会重新识别当前分支。

**处理结果：冲突已解决。** 保留二开的工作区归档服务和实时 Git 刷新链路，只适配拉取请求身份、打开到合并的状态闩锁、归档前权威复核及完整行为测试。

### `f73f65cd7` 桌面和网页端使用 Escape 关闭设置页

**做什么**
桌面和网页端打开设置后可以按 Escape 返回先前工作区；如果当前有下拉菜单或弹窗，则由最上层浮层先关闭，不会同时退出设置。

**对二开的影响**
二开没有上游完整浮层注册架构，因此没有整套搬入。现有下拉菜单和自适应弹窗接入一个轻量、引用计数的活动浮层状态，继续沿用二开现有层级与样式。

**处理结果：冲突已解决。** 增加路由、浮层优先级和无历史工作区回到项目入口的测试。

### `4bfb682cd` 缩短 Playwright 反馈时间且保留行为覆盖

**做什么**
把重复启动工作区或智能体的浏览器用例合并为同一条分步骤流程；纯守护进程测试不再创建浏览器页面；常用模拟流缩短到 2 秒；CI 只在失败重试时录制 trace 和视频，并减少不必要的重复构建。

**对二开的影响**
上游提交基于另一套 `browser/support` 测试目录和每工作线程守护进程架构，不能直接覆盖二开当前根目录 E2E 与单隔离守护进程。测试行为本身可以在现有宿主上适配。

**处理结果：冲突已解决。** 保留二开测试目录、Windows 启动链路和既有产品断言；只合并重复前置流程、稳定采样、daemon-only fixture、短模拟模型与 CI 录制/构建优化。短模拟模型依赖的“不可在产品模型选择器中展示”标记此前未在二开落地，因此同步补齐最小协议、服务端过滤和客户端选择器过滤，并用三层测试确认该内部模型不会暴露给用户。仍有独立意义的命令中心宿主标签测试与导航测试合并，而不是删除覆盖。

## 冲突已解决

### `bffb33ed3` 命令中心支持多词乱序搜索并按相关度排序

**做什么**
命令中心不再把整段输入当成一个连续子串。`short key`、`key short`、`workspace new` 等多个词可以分别命中标题、副标题或关键字；可见文字匹配优先于隐藏关键字，最相关的结果排在前面，修改查询后旧的键盘选择不会误作用于新排序。

**对二开的影响**
二开缺少该提交依赖的共享文本匹配器，只有文件路径匹配器；命令中心本体又已包含二开的根操作、插件贡献和文件搜索，不能直接使用上游完整文件覆盖。

**处理结果：冲突已解决。** 连同 `packages/protocol/src/search/text-match.ts` 手工移植统一评分基础，在二开命令中心现有操作、插件、工作区、智能体和文件分组上适配排序，并补齐单元测试与当前 E2E 宿主可运行的命令中心测试。

## 已丢弃

**做什么**
