## 建议合并

### `8bfae1585` 切分支后当前拉取请求消失,或被已合并的旧 PR 触发误归档

**做什么**
两个问题:一是切换分支后,右侧看不到当前分支对应的拉取请求了;二是自动归档会被一个**早就已经合并**的旧 PR 触发,把工作区错误归档掉。合并后:查状态跟着当前检出的分支走;自动归档必须由守护进程亲眼看到同一个 PR 从"打开"变成"已合并"才执行。

**对二开的影响**
改的是 Git 检出工具层,是二开功能 16(VS Code 式 Git 面板)的服务端支撑。缺失的两个文件都是测试,主体可直接应用。

**建议:合并。** 误归档会让工作区无声消失,属于数据可见性缺陷。合并后验证二开的托管平台状态行和提交图谱刷新未受影响。

## 不跟随(右侧面板策略)

### `c4dc70141` 升级后旧的侧边标签被塞进 Explorer

**做什么**
Explorer 上线后复用了旧 Side 面板的存储标识,导致用户升级时原本普通的侧边标签被错误地灌进 Explorer 停靠区。合并后在版本迁移时把它们移回普通侧边面板。

**为什么不跟随**
纯粹是上游 Side 面板 → Explorer 迁移路径上的善后,二开两者都没有,没有对象可迁。

**结论:丢弃。**

## 缺前置

### `bffb33ed3` 命令面板搜索:多个词分开写就搜不到

**做什么**
命令面板原本把你输入的整串当成一个连续子串去匹配,所以词序、空格必须完全对上:输入 `shortcuts` 能找到"Keyboard shortcuts",输入 `short key` 什么也找不到。而且结果按固定分组排序,最匹配的往往不在第一个。合并后按词元逐个匹配、逐个打分,`short key`、`key short`、`workspace new` 都能命中,并按相关度排序。

**对二开的影响**
**缺前置。** 它依赖上游共享的文本匹配器 `protocol/src/search/text-match.ts`,二开只有 `path-match.ts`,没有这个文件。二开有命令面板本体,但没有这条匹配基础设施。

**建议:想要的话需要手工移植。** 体验提升明显但不是缺陷修复,可以排在后面。若移植,连同 `text-match.ts` 一起引入,不要在二开侧另写一套匹配逻辑。
