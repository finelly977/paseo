## 建议合并

### `a1ed5a8ba` 拉取请求轮询把你整个 GitHub 账号的配额耗光

**做什么**
拉取请求状态轮询按工作区各自计时,每个工作区一次查询。工作区超过 50 个左右时,就会把 GitHub 每小时 5000 点的 API 配额**整台机器耗尽**——不只是 Paseo 用不了,你在这台机器上其他用 GitHub API 的工具也会一起被限流。合并后改成全局调度:所有到期目标凑到同一个 5 秒栅格上,一次批量查询最多 25 个目标。

**对二开的影响**
三个文件在二开都存在,可直接应用。二开功能 16 的托管平台状态行正是这个轮询的消费方。

**建议:优先合并。** 这是本批里影响外溢到 Paseo 之外的唯一一条。

### `fb67d2cdc` Git 排队时守护进程假死、客户端掉线

**做什么**
Git 进程的启动是同步补充的,机器上 Git 启动慢的时候会把主循环占死,占到连接保活检测超时——表现为客户端莫名其妙断线重连。合并后改成每轮事件循环只放行一个进程,空闲时第一条命令会立即执行,不给正常的顺序 Git 操作增加延迟。

**对二开的影响**
中高。改工作区 Git 服务和 Git 命令层,是二开功能 16 的服务端支撑。二开自己做过工作区 Git 刷新优化(`cd99f4f58`,改成首次调度后忽略后续事件),需要确认两套节流不会叠加成"半天不刷新"。

**缺前置:** 它依赖上游的 Git 进程调度器模块,二开没有这个文件,需要连同引入。

**建议:合并,合并后实测一次外部改文件后 Git 状态多久刷新。**

### `23debf3af` 通过 Paseo 提交会绕过你配置的 Git 签名

**做什么**
Paseo 在应用内提交和 squash 合并时强制关掉了签名,你在 Git 里配置的签名策略不生效。合并后交给 Git 按用户配置执行。

**对二开的影响**
二开功能 16 提供了完整的提交流程,这条直接作用在那上面。两个文件都存在,可直接应用。

**建议:合并。** 如果你用签名提交,这是个静默产生未签名提交的缺陷。

### `25eb322ef` 归档掉的工作区又从缓存里冒出来

**做什么**
本地缓存的读取和"目录已被替换"的写入会抢跑,把已经在内存里删掉的记录又读回来——你归档了一个工作区,它过一会儿又出现在侧栏。合并后读取排在待写入之后,主机切换时丢弃在途读取,本地归档在确认删除前不做缓存恢复。

**对二开的影响**
二开功能 1 依赖"重新进入工作区时自动打开最近活跃且未归档的根智能体",归档项复活会干扰这个选择。缺失的两个文件是测试。

**建议:合并。**

### `7ea428811` 恢复的工作区标签陷入死循环,焦点被拽走

**做什么**
启动时重复的标签会把工作区焦点挪到 Explorer;之后清理逻辑删掉过期智能体,空工作区的对账又不断往里塞草稿并重新触发自己,形成循环。合并后在对账边界保留普通面板的焦点。

**建议:合并,注意 Explorer 相关代码在二开是否有对应物。**

## 需要先审计

### `3d69b0f45` Markdown 把 (c) 显示成 ©、把引号变成弯引号

**做什么**
Markdown 渲染器开了"排版美化"选项,会在解析后替换字符:`(c)` 变成 `©`、`...` 变成省略号、`---` 变成破折号、直引号变成弯引号。智能体经常用 (a)(b)(c) 标记选项,渲染出来就成了 (a)(b)©。更麻烦的是,智能体输出的文本你会直接复制到终端或文件里,弯引号在屏幕上看着对,粘贴过去就报错。文件预览也有同样的问题,显示的字符和磁盘上的不一致。合并后原样渲染。

**对二开的影响**
它修改的 `assistant-markdown-parser.ts` 在二开不存在——二开功能 11 自己做了一套共享的 Markdown 解析(`markdown-ast.ts`),文件布局不同。

**建议:值得要,但需要手工移植。** 改动本身很小(关掉一个选项),移植到二开的解析器和 `markdown-styles.ts` 上即可,不要照搬文件。

### `ed628ff82` 把工作区操作加进命令面板

**做什么**
八个原本只能从侧栏菜单、工作区头部菜单或死记快捷键才能用的操作——重命名工作区、复制工作区路径、复制分支名、固定/取消固定、三个布局开关、显示设置向导——全部进命令面板,另外新增标签分配。同时把重命名对话框从侧栏行组件里挪出来,否则那一行没渲染时(项目折叠、分组折叠)对话框会跟着消失。

**对二开的影响**
**缺前置。** 修改的 11 个文件里有 5 个在二开不存在,是上游 0.5.0 引入的命令面板工作区贡献点。同时压在二开功能 14(行菜单关闭后悬停残留)、18(侧栏组织方式)、1 上。

**建议:待定。** 想要的话得先补命令面板的工作区贡献点。重命名对话框那部分修复本身有价值,可以单独手工移植。
