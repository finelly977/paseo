本标签有两条 OpenCode 可靠性修复和一条测试基建修复(都可直接合)。主体 Explorer 重构按右侧面板策略不跟随,但从中摘出了一条值得单独做的窗口控件能力。

## 建议合并

### `54299a2e6` OpenCode 首次连接卡住就直接判定回合失败

**做什么**
OpenCode 启动时如果第一次事件流连接卡住,等待就绪的超时和内部看门狗在同一时刻到期,导致已经在进行的重连来不及救回这次对话——回合直接失败。合并后允许那次重连落地,并保留真实的失败原因用于日志和错误提示。

**对二开的影响**
二开有 `ac90cef63`(增强 OpenCode 事件流断开后的会话恢复),但那条处理的是**运行中断线**,这条处理的是**启动阶段首次连接**,是不同的失败窗口。5 个文件在二开都存在,可直接应用。

**建议:合并。** 合并前快速确认两者的超时窗口不会互相抵消。

### `6f6466d4c` OpenCode 还没连上就开始发提示词

**做什么**
Paseo 在 OpenCode 报告"连接已就绪"之前就把提示词发出去了,靠一套自己伪造的重连约定兜底。合并后改为等待提供方真实的连接事件,后续连接事件直接触发已有的补洞逻辑。

**对二开的影响**
和二开功能 17(启动阶段按需初始化)方向相关但不矛盾:二开推迟的是**探测哪些提供方可用**,这条管的是**已选提供方连上了没**。6 个文件在二开都存在,可直接应用。

**建议:合并。** 合并后确认没有退回"一连上就探测全部提供方"的行为。

### `f4b5f3286` Playwright 测试在 Windows 上根本起不来

**做什么**
浏览器端 E2E 测试的启动脚本在 Windows 上无法运行(用 `spawn("npx")` 和 `which tsx`,前者是 Windows 批处理外壳、后者在 Windows 不存在)。改成直接用 Node 可执行文件启动,POSIX 上行为不变。顺带修了发布版服务端在 Windows 上的 npm 安装失败。

**对二开的影响**
纯测试基建,无产品行为改动。

**建议:合并。** 二开主力开发环境是 Windows,这条直接让你能在本地跑浏览器测试。

## 新能力候选

### `c914bcb44` 里夹带的自定义 Windows / Linux 窗口控件

**做什么**
应用自己绘制最小化 / 最大化 / 关闭按钮,替代操作系统默认的窗口边框控件,让标题栏和应用界面连成一体。

**为什么单独列出**
它被压在 Explorer 重构那个 191 文件的提交里,但和右侧面板毫无关系。新增文件是 `packages/app/src/components/desktop/window-controls.tsx`,二开没有(二开只有配套的 `titlebar-drag-region.tsx`)。

**处理结果：已单独摘取并适配。** 只引入窗口模式、Electron 桥接、自绘控件、状态同步、安全区和挂载点，其余 Explorer 与右侧面板改动全部丢弃。

## 不跟随(右侧面板策略)

按 [README 的右侧面板策略](../README.md#右侧面板不跟随上游结构),下列条目不合并。

### `c914bcb44` Explorer 侧栏重构(191 文件)

**做什么**
上游 0.5.0 把右侧改成用户自己加标签的"Side 面板",反响不好;0.6.0 换回专用的 **Explorer 侧栏**,默认带"文件"和"更改"两个视图。同时带来:逐项设置文件/更改/子智能体/拉取请求开在主面板还是侧边、Explorer 内新建标签和拖拽、差异作为独立标签打开。

**为什么不跟随**
二开已经完全重构了右侧 Git 面板并改造了文件面板,这套结构在二开没有对应物——它修改的 144 个文件里有 56 个在二开不存在。合并等于把二开的右侧面板推倒重来。

上游列出的那几项"新能力"(打开位置设置、Explorer 内拖拽、独立差异标签),二开的面板要不要做是**独立的产品决定**,和合不合这个提交无关。

**结论:丢弃结构改动,窗口控件已单列到上一节。**

### `bbe3f1732` / `614799151` 配套测试预期调整

只为配合 Explorer 重构调整子智能体位置和启动器顺序的测试预期。

**结论:丢弃。** 随 `c914bcb44` 一起。

## 已合并

- `54299a2e6`：OpenCode 首次事件流连接卡住时，允许消费器完成一次重连；失败报告保留尝试次数、阶段、等待时间和底层错误，提示词在连接就绪前不会发送。
- `6f6466d4c`：OpenCode 改为等待提供方真实的服务连接事件；首次连接事件只负责放行提示词，后续连接事件直接触发既有的遗漏内容修复，不再使用自造的“已重连”消息。
- `f4b5f3286`：按二开当前 E2E 目录结构适配 Windows 启动链路。Expo、tsx 和 npm 脚本均由 Node 直接启动，清理时终止完整进程树，冷启动等待预算提高到 90 秒，并为假编辑器和 GitHub CLI 生成 Windows 命令包装文件。
- `c914bcb44` 中独立的窗口能力：Windows 和 Linux 桌面端改用应用自绘的最小化、最大化、还原和关闭按钮；按钮与二开 48 像素标题栏、主题和右上角安全区对齐，macOS 继续使用系统交通灯。开发版本可在 macOS 预览两种自绘模式。

## 冲突已解决

- OpenCode 可靠性修复合并到二开已经切换的全局事件流实现中，保留二开完整错误日志、运行中断流恢复和按需提供方初始化，不恢复旧的目录事件流或轮询兜底。
- Windows E2E 修复适配到二开已经扁平化的测试目录，没有恢复上游已删除的 `support` 目录；按用户要求未运行 Playwright，只运行类型检查和 Node 侧定向测试。
- 自绘窗口控件只摘取独立的 Electron 主进程、预加载桥接、客户端控件、状态同步和安全区能力；未引入 Explorer、Side 面板、上游 Git 面板或文件面板结构。

## 已丢弃

- `c914bcb44` 的 Explorer、Side 面板、Git 面板、文件面板、标签宿主和打开位置结构：与二开长期维护的右侧面板和正文标签体系冲突，仅保留独立窗口控件能力。
- `bbe3f1732`、`614799151`：只调整 Explorer 重构后的子智能体位置和启动器顺序测试，二开没有对应结构。
