## 需要你决策

### 1. `a8734a972` 许可证从 AGPL-3.0 改为 Apache-2.0

**做什么**
上游把 `LICENSE` 和所有 `package.json` 的 license 字段从 `AGPL-3.0-or-later` 换成 `Apache-2.0`,同步改了四种语言的 README 和两篇文档。

**对二开的影响**
Apache-2.0 比 AGPL 宽松,取消了"提供网络服务也必须开源"的义务。二开目前继承 AGPL。跟不跟随是**法律决定,执行者不得自行选择**。

**必须注意:这个提交是混装的。** 71 个文件里只有约 10 个和许可证有关,其余是完全不相干的功能改动:

- 桌面主进程重构(`main.ts` 减 248 行)和新增的窗口归属模块
- 新增浏览器截图功能、"用外部程序打开"逻辑重写
- 桌面守护进程管理器改动——正好压在二开功能 17(预启动内置守护进程)上
- 应用侧的加密垫片、项目工具、侧栏固定钩子
- CLI 的 `agent ls` 命令

**建议:拆开处理。** 许可证部分单独取舍;桌面窗口重构和守护进程管理器改动当作普通功能提交另行分诊。整体 cherry-pick 会在你毫无准备的情况下改掉桌面守护进程行为。

### 2. 插件体系(9 个提交,新增 `packages/plugin` 工作区,约 74 个文件)

**做什么**
一整套第三方扩展机制:插件可以从 Git 仓库直接安装和更新、自定义时间线条目的显示方式、使用宿主提供的图标和主题色、读取已注册项目列表。附带新的 CLI 命令、示例插件和文档。

涉及提交:`f82886f28`、`8e0af11b6`、`7ae5133ed`、`ecfb77b01`、`12e3acd18`、`4de913fb8`、`4c46f2017`、`657152c47`,以及 `v0.7.0-beta.2` 的 `deb846eed`、`fe803f6e7`。

**对二开的影响**
**缺前置。** 二开完全没有插件体系(上游 0.5.0 引入),这整条线是从零引入。主要风险点是 `7ae5133ed` 要求对话视图开放"让插件改写时间线条目"的接口——那正是二开功能 5、6、11 重度改造的文件。

**建议:待决策。**

- 不打算支持第三方插件 → **整体丢弃**是干净的选择,代价是与上游对话视图的结构分歧继续扩大。
- 打算支持 → **整组一次性引入**,不要零散挑选,否则会得到一个残缺的扩展接口。

其中 `657152c47`(SDK 暴露已注册项目列表)是唯一能脱离插件体系单独合并的,风险低。

### 3. 副本缓存改行存储(`b12daabe3` 等 5 个提交)

**做什么**
把应用本地那份"离线副本缓存"(用来在连上主机之前先把上次的对话画出来)从整块存储改成按行存储,目的是让长对话的重启恢复更快、写盘更省。涉及 `b12daabe3`、`579c6a58f`、`f59db03d6`、`fd22784e2`、`0f68e55ec`。

**对二开的影响**
**冲突面最大的一项。** `b12daabe3` 一次改 232 个文件(它同时是一个混装的压缩提交,里面还夹带了 Hub 引导设置等无关功能),覆盖对话视图的间距、布局、虚拟化、网页渲染策略全家桶,以及会话状态仓库和应用根布局——正好是二开功能 5(对话排版间距)、6(历史索引与消息跳转)、11(成功回合折叠)、13(常驻界面渲染)的全部核心。它修改的 150 个文件里有 46 个在二开不存在。

**关键风险:** 二开功能 6 明确规定"应用重启后从本地缓存副本恢复的会话必须按配置重新权威加载,缓存尾部不得当作已同步的完整历史,也不得用它的陈旧光标走增量路径"。上游这次重构改的正是这份缓存的存储粒度。合并前必须先确认这条不变量在新结构下怎么表达,否则会静默退回旧缺陷——表现为打开老会话时历史加载不全,而且不报错。

**建议:待决策,优先级排在许可证和插件之后。** 收益是性能,代价是重做二开对话视图的四条功能,不值得先动。

## 建议合并

### `59e623278` 权限请求被取消后,权限卡片一直卡在那里

**做什么**
提供方有时会在用户还没点选之前就取消一个权限请求。这时 Paseo 收不到结束事件,界面上那张"是否允许"的卡片就永远停在等待状态。合并后为这种情况补发一个明确的结束事件。

**对二开的影响**
两个文件在二开都存在,可直接应用。方向和二开功能 16 一致——二开的提交审查浮窗同样依赖权限结束事件才能收尾。

**建议:合并。**

### `96cf0f2ae` 升级 Claude Agent SDK 到 0.3.246

**做什么**
把 Claude Agent SDK 从 0.3.220 升到 0.3.246,保持精确版本锁定。上游说明称类型接口只增不减。

**对二开的影响**

另外它修改的 `claude/options.ts` 在二开不存在(二开的 Claude 适配器文件布局不同),需要手工对应。

**建议:合并,但升级后必须实测一次后台子代理场景。** 二开有 `agent.background-tasks.test.ts`,先跑它。

## 需要先审计

### `e22ad117f` / `dac6cd141` 助手文字一顿一顿地往外蹦

**做什么**
智能体输出的文字是按 60 毫秒一批送过来的,每批里的字数随模型输出速度剧烈波动,而界面收到多少就画多少——看起来就是一卡一卡地往外蹦。合并后改成匀速渲染,视觉上像稳定打字。

**对二开的影响**
高。改对话视图和消息组件,是二开功能 5、11 的核心文件。好消息是它修改的 11 个文件在二开**全部存在**,可直接应用。

**建议:合并,但要盯住二开功能 11 的"回合成功后收起中间过程"。** 匀速渲染改变了文字到达的节奏,确认收起时机不会被推迟。按上文"重复提交"提醒取净差异。

### `e19d3914a` / `c3ae54a1a` 回退长对话时整个历史重新加载一遍

**做什么**
回退对话后,守护进程会重建时间线。旧做法是把重建后的历史整个重放一遍,长对话看起来就是"从头重新加载"。合并后有能力的客户端改成只刷新已有的尾部,老客户端仍走重放。

**对二开的影响**
高。改智能体管理器、提示词处理、客户端能力声明和回退组件,正好压在二开功能 4(Codex 与 Claude 使用不同的原生回退策略)上。缺失的三个文件都是测试。

**建议:合并,必须逐条对照功能 4 审计。** 二开的 Codex 是原地回退、Claude 是分支出新会话,两种路径下"时间线被替换"的信号语义不同,别让新的尾部刷新路径把其中一种漏掉。按上文取净差异。

### `0ad69d3eb` 重启后要等半天才看到对话内容

**做什么**
冷启动时,应用会先把所有保存过的主机全部恢复一遍,再发布任何会话。于是一份本地已经缓存好、完全可以立刻画出来的对话,被卡在无关的目录校验和网络就绪后面。合并后缓存内容按需直接绘制,网络回来后再权威对账。

**对二开的影响**
高。51 个文件,涉及会话状态仓库、会话上下文、客户端活动心跳、工作区界面和侧栏模型,覆盖二开功能 6、7、13。而且它**依赖副本缓存行存储重构**(缺 `row-store-sqlite.ts`),属于上文第 3 项决策的下游。

同样要盯二开功能 6 的那条不变量:缓存先画出来没问题,但不能因此认为历史已经加载完整。

**建议:等副本缓存决策之后再处理。** 单独合并会缺前置。
