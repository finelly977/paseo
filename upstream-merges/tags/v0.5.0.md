## 二、当初跳过的功能线,及其处理方式

这一节是本次补记的重点。下面每一条都不只是"少个功能",而是**让 0.6 / 0.7 的若干提交无法直接 cherry-pick**。其中右侧面板相关的两条已按策略定为不跟随,不再算待解决项。

### 1. Side 面板 + New tab 启动器 —— 不跟随

**做什么**
0.5.0 把右侧改成用户自己往里加标签的"Side 面板",并给面板加了浏览器式的"新建标签"入口:点 + 号选择要开智能体、终端、文件还是差异。

**结论:不跟随,按 [README 的右侧面板策略](../README.md#右侧面板不跟随上游结构)。**

上游自己在 0.6.0 就把 Side 面板换成了 Explorer,补一个已废弃的中间形态本来就没意义;二开又已完全重构了右侧面板,整条线不再跟随。

**连带丢弃:** `v0.6.0` `c914bcb44`(Explorer)、`v0.6.1` `c4dc70141`(布局迁移)、`v0.7.0-beta.1` `46b401eac`、`5a38a3334`、`2124115c8`。这些不再算"缺前置待解决",而是**已决定不做**。

### 2. 命令面板的工作区操作贡献点

**做什么**
让命令面板能列出并执行工作区级别的操作(重命名、复制路径、固定、布局开关等),而不只是搜索和跳转。

**注意:这条其实来自 v0.3.0(#2749),不是 0.5.0。** 0.5.0 的 #3685 是在它之上继续扩展。二开有命令面板本体,但没有这套贡献点机制。

**挡住了什么:** `v0.7.0-beta.2` `ed628ff82`(把八个工作区操作加进命令面板)缺前置。

**建议:值得补,优先级中等。** 它是个自足的扩展点,补进来之后 `ed628ff82` 就能正常合,而且以后上游往命令面板加东西都不会再卡。

### 3. 拉取请求检查结果汇总 —— 不跟随结构

**做什么**
拉取请求面板里把 CI 检查按结果分组、失败的排前面,并显示汇总。

**结论:结构不跟随。** 拉取请求面板属于二开重构范围。

**但保留一个新能力候选:** `v0.7.0-beta.1` `b79b4bd5f` 在此之上给 GitLab 和 Gitea 的检查增加了"需要手动触发""需要你操作""警告"三种状态。这是真实的新能力——只有你实际用 GitLab 或 Gitea 才值得在二开自己的面板上做一个;用 GitHub 的话直接丢弃。

### 4. 插件体系

**做什么**
0.5.0 引入受信任的本地插件(实验性),以及插件贡献的应用主题。0.7.0 继续扩展成可从 Git 安装、可改写时间线渲染的完整体系。

**挡住了什么:** `v0.7.0-beta.1` 和 `beta.2` 的全部 plugin 提交(约 10 个)。

**建议:整体决策,见 [v0.7.0-beta.1.md](v0.7.0-beta.1.md)。** 如果不打算支持第三方插件,这条永远不用补,只需接受二开的对话视图会和上游持续分叉。

### 5. 共享文本匹配器 / Git 进程调度器(实为 v0.3.0 遗留)

这两条**不属于 0.5.0**,但在核对时一并发现,记在这里以免下次再查一遍:

| 共享文本匹配器 | v0.3.0 #2995 | `v0.6.1` `bffb33ed3` 命令面板多词元搜索排序 |

## 三、当初跳过,不挡路,可按需补

按对二开的实际价值排序:

### `paseo reload`:改完 config.json 不用重启守护进程(#3365)

改动 `config.json` 后可以让守护进程热加载运行时安全的部分,不必重启。**对二开尤其有用**:项目规则明确禁止随意重启 6767 端口的主守护进程,而重启是目前应用配置改动的唯一途径。

**建议:值得补。**

### 主机设置里管理 Paseo 技能(#3451)

在 Host → Agents 里管理技能,远程主机也支持。二开设置页没有这一节。

**建议:按需。** 你如果用技能就补。

### `paseo project` 命令(#3460)

终端里创建、列出、重命名、删除项目。二开 CLI 没有 `project` 子命令。

**建议:按需,价值取决于你是否用 CLI 做自动化。**

### 分开设置聊天/输入框/Markdown/审阅的字号(#3637)

给不同区域独立的正文字号。二开功能 5 已经自己做了一套间距的像素级设置,但那是**间距**不是**字号**,两者不重叠。

**建议:按需补,注意和二开功能 5 的外观设置页合并成一处,不要开两个入口。**

### 子智能体和任务跟踪改成输入框上方的胶囊(#3482)

二开有子智能体轨道(`subagents/track.tsx`),但是旧形态。这条是把它和任务跟踪一起改成更紧凑的胶囊。

## 五、0.5.0 尾部的九条修复

以下条目按提交区间归属从 [v0.5.1.md](v0.5.1.md) 移入。

### `71e375c2b` 查询用量额度会写坏提供方的登录文件

**做什么**
Paseo 后台查询你在各智能体提供方的用量额度时,会往提供方存放登录凭据的文件里写东西。合并后额度查询只读不写。

**对二开的影响**
无交集,可直接应用。

**建议:合并。** 会损坏登录状态的缺陷,和二开无关。

### `5123b23f4` 项目图标里有普通 CSS 写法就会让整个应用崩溃

**做什么**
Paseo 会自动扫描项目里的 `favicon.svg` / `icon.svg` / `logo.svg` 当项目图标。如果这个 SVG 写了 `style="transform:none"` 这类普通 CSS 值(而不是 SVG 专用的 transform 函数),解析器直接抛异常,**整个应用在渲染时崩溃**。只要你打开的某个仓库里恰好放了这样一个图标文件,应用就打不开。合并后遇到看不懂的写法就忽略。

**对二开的影响**
无交集,可直接应用。

**建议:合并。** 触发条件由别人仓库里的文件决定,你无法预防。

### `8d92e1cc1` 配对链接的风险提示写错了

**做什么**
手机扫码配对生成的链接,实际等同于交出守护进程的完整访问权,而且守护进程重启后依然有效。旧界面写的"链接会轮换"是错的。合并后换成正确的风险提示。

**对二开的影响**
无交集,可直接应用。

**建议:合并。** 纯文案,但纠正的是一条会误导人的安全说明。

### `35cde075a` 手机端输入框切换会话后不再自动变高

**做什么**
iOS / Android 上的多行输入框,在切换工作区或切换智能体之后就不再随内容自动增高,删掉文字后高度也不回缩。合并后改由原生输入框自己管尺寸,网页端保持原有测量方式。

**对二开的影响**
只动原生端输入框,二开未改这条路径,可直接应用。

**建议:合并,且必须和 `v0.5.1` 的 `e268d1a89` 一起。** 两者修的是同一个问题的两个面,拆开会留下半截状态。

### `c3594b207` 固定最后一个工作区后,项目从侧栏消失

**做什么**
把某个工作区固定到侧栏顶部后,如果那是该项目下的最后一个工作区,项目本身就从列表里消失了,于是你再也没法在这个项目下新建工作区。合并后保留一个空的项目行。

**对二开的影响**
二开功能 18 改了侧栏的组织方式和行高,合并后需确认固定区在紧凑父子层级下显示正常。

**建议:合并,合并后手动看一眼侧栏。**

### `397937190` 点"停止"后智能体卡在运行中,没法开始新对话

**做什么**
你点停止打断智能体时,如果提供方那边其实已经自己停下来了,Paseo 收不到预期的确认,就一直认为回合还在跑——智能体卡在"运行中",你发不了新消息。合并后 Paseo 把"已经是空闲"当作有效的停止结果并放行。另外还修了 Codex 在回合刚启动那一瞬间被打断时,会留下没人管的后台工作。

**对二开的影响**
高。同时改智能体管理器、提供方接口定义和 Codex 适配器,正好压在二开功能 10(Codex 容量已满自动恢复)、11、12(Claude 后台子代理保活)上。缺失的只有一个测试文件,主体可应用。

**建议:合并,但必须逐条对照功能 10 和 12 审计。** 二开的容量重试也会"原地回退并重发",和这里的停止确认语义相邻,别让两套逻辑互相抵消。

### `4094eeb56` 加载失败后的重试退避被切标签绕过

**做什么**
对话历史加载失败后会自动重试,间隔逐次拉长。但切换标签、改动布局这类跟网络无关的动作被误当成"用户要求立即重试",于是失败的加载被反复重启,退避形同虚设——表现为一直在转圈重试。合并后只有你主动点重试才立即重试。

**对二开的影响**
二开功能 11 已经自己实现了"1 秒起、最多 30 秒"的退避。上游修的是**退避被误触发绕过**这个更底层的问题,二开的实现很可能有同样的漏洞。

**建议:先看二开的重试是否也会被可见性变化重置。** 如果会就合并;如果二开已经规避,则丢弃并在功能 11 里注明。

### `2124115c8` 点"+"号时在鼠标旁边弹出标签选择菜单

**做什么**
点面板上的 + 号新建标签时,在鼠标旁边弹一个小菜单选要开什么,而不是打开一个占满面板的"新标签页"。键盘和空面板仍走整页选择器。

**对二开的影响**
**缺前置。** 修改的 8 个文件里有 6 个在二开不存在——New tab 启动器是本区间的 #3715 引入的,二开没挑。本提交只是给已有启动器换个呈现方式。

**结论:丢弃。** 右侧面板整条线已定为不跟随,见第二节第 1 条。

### `dc9fb9aa1` 窄屏下把有后果的 Git 操作收进菜单

**做什么**
窄屏时 Git 工具栏按钮太多,把放弃更改这类有后果的操作收进菜单,只保留窄工具栏。

**对二开的影响**
二开功能 16 已经把整个右侧 Git 面板重写成 VS Code 式工作流,并自己定义了紧凑密度和操作菜单收纳规则。

**建议:丢弃。** 合并只会制造冲突而不带来行为收益。
